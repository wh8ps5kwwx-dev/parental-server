Privacy Policy

Last updated: July 2026

This policy describes how the MYRana graduation project (parent app حماية الأطفال, child app أكاديمية العباقرة) handles data in the implemented Android / Flutter clients and the Flask server on Render. It reflects actual collection in the codebase — not hypothetical marketing features.

1. Who this applies to

Guardians who verify email and link child devices, and children whose devices run the academy / monitoring client under family supervision (target age roughly 5–13).

2. Data we collect

  • Guardian email — for registration / login and OTP verification (Gmail / Resend).
  • OTP / email codes — short-lived verification and parent–child link codes.
  • Child device code — identifiers such as CHILD-XXXXXXXX and child display names.
  • Linking & device records — guardian–child relationships and device registration status.
  • Usage statistics — app usage / foreground time derived from Android Usage Access.
  • Screen-time events & policies — daily limits, sleep schedules, and related events.
  • Blocked apps & sites — package names, blocklists, and content-filter matches (Accessibility).
  • Commands & policies — block / freeze / allow and other guardian commands synced to the child.
  • Alerts & reports — content/usage alerts and aggregated activity reporting data.
  • Heartbeat / status — online status and permission readiness (e.g. Usage Access, Accessibility).
  • Installed app metadata — as needed for parent app lists and blocking (where implemented).
  • Guardian messages — text messages sent from parent to linked child devices.

3. Data we do not collect

  • GPS / precise location — the apps do not request location permissions or store coordinates.
  • Continuous microphone or camera surveillance — not part of the implemented monitoring stack.
  • Payment / banking data — this is an educational project, not a commercial billing product.

4. How data is used

  • Authenticate guardians and securely link child devices.
  • Enforce parental policies (blocks, screen time, content filtering) on the child device.
  • Show dashboards, alerts, and reports to the linked guardian.
  • Operate the disguised child experience (أكاديمية العباقرة) alongside background enforcement.

5. Storage & transmission

Data is transmitted to the project’s Flask API over HTTPS (Render deployment). The server uses SQLite for persistence; child devices may keep local Room / policy caches and sync when online. Email OTP delivery uses configured SMTP / Resend credentials on the server environment.

6. Permissions on the child device

Monitoring depends on Android Usage Access and Accessibility (plus related notification / battery settings when prompted). These permissions enable usage reporting, app blocking, and site/content filtering — not location tracking.

7. Sharing

Data is shared between the linked guardian account and the associated child device(s) through the project server. There is no sale of personal data. Third-party processors are limited to infrastructure needed to run the demo (e.g. Render hosting, email delivery for OTP).

8. Retention

As a graduation / demo deployment, retention may be limited by hosting disk policy and redeployments. Guardians should treat the live Render instance as educational infrastructure, not a long-term archive.

9. Children’s privacy

The system is intended for family use under guardian responsibility. The child UI is educational/game-oriented; monitoring data is for the linked parent account. Guardians should install and configure the child app with informed consent within the family.

10. Contact

For questions about this graduation project’s privacy practices, use the contact form on the landing page.
